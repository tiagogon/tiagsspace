When a change in the codebase invalidates or contradicts information in this file (e.g. renaming files, adding/removing post types, changing directory structure), update this file immediately to reflect the new state. This avoids re-explaining context in future sessions.

Never edit the bootstrap.css file. All style editing needs to be done via .scss files.

Never edit files inside library/js/ subdirectories (e.g. intense-images, plyr, masonry, etc.). These are third-party libraries that may be updated from their upstream repositories — any custom edits would be lost on update. Instead, apply fixes or overrides via custom SCSS or separate wrapper scripts.

Never check how the SCSS is compiled. I will always ensure I have Koala running in the background when working with you.

## Theme structure

This is a custom WordPress theme called "tiagsspace" (Tiags' Space). It uses a custom 48-column Bootstrap grid (not the default 12-column).

### PHP files
- `functions.php` — theme setup: enqueues, theme supports, responsive image helper (`tiagsspace_render_picture_from_attachment()`: srcset thumbnail → small → medium → large → **xlarge only when that file exists** (WordPress returns the ORIGINAL under the size's width for a missing size; in Nov 2026 only 350 of ~3,000 uploads wider than 1920 had one) → original; optional `$img_attrs` for loading / decoding / fetchpriority), thumbnail sizes, upload mimes, favicons, archive title cleanup, misc hooks. Requires all `library/*.php` files.
- `library/helpers.php` — WordPress cleanup utilities (head cleanup, pagination, excerpt formatting, image p-tag filter). **Core's emoji replacer is off** (`tiagsspace_disable_emoji()` on `init`, `tiagsspace_disable_emoji_admin()` on `admin_init` — the admin hooks are added by `wp-admin/includes/admin-filters.php` *after* `init`, so an `init`-only removal misses wp-admin): WP's loader tests the browser against the newest emoji it knows (WP 7.1: Emoji 17), any OS a release behind fails and gets every emoji swapped for Twemoji SVGs from s.w.org. Without it the OS font draws them: Apple Color Emoji on Mac/iPhone/iPad, Segoe on Windows, Noto on Android. Apple's look cannot be forced on other platforms (the font is not licensed for the web).
- `library/video/` — **Portable self-hosted video module** (Plyr-based; no ACF/theme coupling inside — callers pass values via `$args`, so the folder copy-pastes into other themes like lento.world). The `self_host_film` attachment on a film is the mode switch: an **`.m3u8`** attachment plays via **HLS**, any other video plays the **progressive MP4 ladder**.
  - `player.php` — `render_video_player($args)` dispatcher + shared helpers (`tiagsspace_video_is_hls()`, poster via `xlarge`, caption tracks from `_kgvid-meta`, Plyr config builder from `player_options`).
  - `player-mp4.php` — progressive MP4 renderer: builds a de-duplicated, correctly-typed quality ladder from the original + Videopack child attachments. A `.mov`/quicktime master is included as a selectable rung with its real MIME (`video/quicktime`) — Safari/Chrome/iOS play it, Firefox skips that `<source>` and uses the MP4 rungs. The default quality (largest ≤1080) is emitted first in DOM so browsers never auto-load the big master; `preload="metadata"`.
  - `player-hls.php` — HLS renderer: single `<video>` with the `master.m3u8` source + `data-hls-src`.
  - `enqueues.php` — registers module JS with `filemtime()` versions; `tiagsspace_video_enqueue_mp4()` (loads `plyr-adaptive-quality.js`) vs `tiagsspace_video_enqueue_hls()` (loads `hls/hls.min.js` + `video-player/init-hls.js`). Also defines `tiagsspace_asset_ver()`.
  - `hls-import.php` — Media Library import: drag a `<slug>.hlspack.zip` (built by `bin/hls-package.sh`), the `add_attachment` hook unzips it to `uploads/hls/<attachment-id>/`, re-points the attachment at `master.m3u8` **renamed to `<slug>.m3u8`** (MIME `application/vnd.apple.mpegurl`), deletes the zip; `delete_attachment` removes the folder (path-guarded). Logs to `uploads/hls/import.log`; failures show an admin notice and leave the zip intact. Allows `zip`/`m3u8` in `upload_mimes`. Writes `_tiagsspace_hls_dir` meta (`hls/<id>`), which `hls-subtitles.php` uses as its bundle locator.
  - **CAPTIONS ON HLS FILMS — READ THIS BEFORE TOUCHING ANY OF IT.** Sidecar `<track>` elements are a DOM concept with **no AVPlayer media-selection group**, so iOS lists nothing and draws nothing for them in native fullscreen. The only thing iPhones render is **in-manifest `EXT-X-MEDIA:TYPE=SUBTITLES` renditions**. Three parts:
    - `library/video/hls-subtitles.php` — generator (portable, no ACF). Writes `uploads/hls/<id>/subs/<lang>/` and patches the **renamed `<slug>.m3u8`** (never `master.m3u8`), idempotently via a pristine `<slug>.orig.m3u8` kept on first run. Sets `_tiagsspace_hls_subs`. **The segment format is proven on device — do not "tidy" it without re-testing on a real iPhone:** 6s segments, **absolute** cue timestamps, identity `X-TIMESTAMP-MAP` in *every* segment, boundary-spanning cues repeated (RFC 8216 §3.5). `EXT-X-MEDIA:URI=` must stay **relative**. No video is re-encoded.
    - `library/film-captions.php` — ACF glue (kept out of `library/video/` for the portability contract). Caption rows live on the **`.m3u8` attachment** (ACF group `group_69a2f1a4c0e11`, location `attachment == application/vnd.apple.mpegurl` — ACF matches full mime types when the rule value contains a slash). Regenerates on `acf/save_post` and after a bundle re-import (unzipping wipes `subs/`). WP-CLI: `wp tiagsspace hls-subs [id]`.
    - **`init-hls.js` routes iPhone/iPod manifest-subs films to NATIVE HLS, skipping Plyr entirely** — inline as well as fullscreen (`film-player--native`). This override sits *before* the `Hls.isSupported()` check because **iOS 17.1+ ships ManagedMediaSource**, so hls.js would otherwise claim the phone; hls.js builds subtitle tracks in JS, which AVPlayer lists but never paints. iPad reports as Macintosh and keeps hls.js + the Plyr UI. `player-hls.php` drops sidecar `<track>`s whenever `_tiagsspace_hls_subs` is set (otherwise hls.js merges both sources and every cue renders twice), and ships a captions-disabled Plyr config that `init-hls.js` re-enables **on the hls.js path only** by rewriting `data-plyr-config` (Plyr merges defaults → options → attribute, so the attribute wins).
    - Accepted trade: iPhone viewers get Apple's player and **system caption styling**, which our SCSS cannot reach. Captions beat the skin.
  - Client JS: `library/js/video-player/init-hls.js` (hls.js wherever MSE is available — preferred over Chrome's native HLS because native ignores `capLevelToPlayerSize`; native HLS only on Safari/iOS; `?video_debug=1` logs the engine, ladder and ABR level switches). It runs hls.js with `subtitleDisplay = false` and bridges Plyr's caption choice to `hls.subtitleTrack` (`bindSubtitleSync`): hls.js otherwise re-derives the rendition from text-track modes and paints its own pick natively on top of Plyr's overlay, visibly so in Firefox, which has no `::-webkit-media-text-track-container` to hide; `library/js/plyr-adaptive-quality.js` is the **MP4 films only** hand-rolled adaptive engine (minimal maintenance — convert a film to HLS rather than extending it).
  - **HLS films have no quality menu on any browser** — ABR picks the rung, and the viewer gets no override. `player-hls.php` passes `['settings' => ['captions']]` as the `$overrides` arg to `tiagsspace_video_build_config()` to drop the pane; the base config in `player.php` still lists `quality` so **MP4 films keep their menu** (they have no ABR to fall back on). Don't "fix" this by editing the shared base config. The settings cog hides itself entirely on an HLS film with no caption tracks.
  - **`library/js/video-player/fullscreen-on-play.js`** — shared by both playback paths (registered once in `enqueues.php`, enqueued from both `tiagsspace_video_enqueue_mp4()` and `tiagsspace_video_enqueue_hls()`). A document-level delegated click listener in the **capture phase** on `[data-plyr="play"]` — not a Plyr `play`-event handler, because `requestFullscreen()` needs transient user activation and only the click itself is reliably inside that gesture. Scoped to `video.film-player` (films only, never gallery/`[KGVID]` videos) and skips films with `loop` or `autoplay` set (ambient by intent, must not seize the screen). On iPhone this hands playback to **Apple's native player** via Plyr's `iosNative: true` (`webkitEnterFullscreen`), replacing the Plyr skin for the duration; iPad and everything else get real fullscreen with the skin intact. By design, fullscreen re-triggers on every play including a deliberate resume after the viewer exited — not a bug.
  - **`library/js/video-player/ios-native-captions.js`** — registered/enqueued alongside `fullscreen-on-play.js` for both playback paths. Fixes captions vanishing in **iPhone fullscreen**: Plyr force-demotes every text track to `mode="hidden"` and paints cues into its own `.plyr__captions` div (`captions.update()` and `captions.toggle()`, which re-hides `currentTrackNode` even when captions are being turned *on*), so once `webkitEnterFullscreen()` hands the element to Apple's player neither renderer draws anything — the overlay is off-screen and the track is hidden. Plyr itself has **zero** `webkitbeginfullscreen`/`webkitendfullscreen` handling. This script **supervises the whole fullscreen window** (300ms interval, killed on exit) rather than promoting once: a one-shot promotion loses to Plyr's deferred re-hide and to manifest tracks arriving after the play-click fullscreen entry. Rules: re-promote when the wanted track drifts to `hidden` (that's Plyr — Apple's Off sets `disabled`, which is respected and stops the supervisor), adopt whatever the viewer picks in Apple's menu, restore everything to `hidden` on exit. iOS draws cues in the viewer's **system caption styling**, which our SCSS cannot reach — that is the accepted trade. Listeners are bound **per `<video>`, not delegated**, because those two events do not bubble; the Plyr instance is still resolved at event time. Leaving a track on `showing` while inline would double up with the Plyr overlay, which is why exit must restore `hidden`. iPad is unaffected (reports as desktop Safari, keeps the Plyr overlay).
  - `bin/hls-package.sh` — local ffmpeg script (Mac; accepts `.mov`/`.mp4`) building the fMP4 HLS ladder → `<slug>.hlspack.zip`; `--thumb`/`--fallback` extras. Ladder entries (2160/1080/720/480/360) are 16:9 **boxes** the picture is fitted into with its aspect ratio preserved and never padded; a box is used only if it needs no upscaling, and per-rung bitrate scales with the real pixel count. So sub-4K masters just shorten the ladder, and a 2.39:1 4K master tops out at 3840x1608 rather than a padded 1920x1080.
  - **Caption styling per film** — ACF selects on the film post (group 6 "Video Player Options" in `acf-fields.php`): `caption_color` (white / yellow / custom + `caption_color_custom` colour picker) and `caption_contrast` (box / shadow). `template-parts/entry-video-player.php` whitelists them and puts only non-default values on `.embed-container`: an inline `--plyr-captions-text-color` (Plyr's own custom property, read by `plyr.css`) and a `captions-contrast--shadow` class styled in `_component-plyr.scss`. Caption font sizes live in the `tiagsspace-caption-sizes` mixin there, applied to inline and fullscreen selectors alike. iPhone's native player ignores all of it (system caption style).
  - **Videopack (video-embed-thumbnail-generator) stays in active service** for archive thumbnail loops (`archive-grid.php` `kgflash_video` meta), gallery videos, and `[KGVID]` shortcodes (`entry-gallery.php`). Only *films* use the HLS/MP4 module. `hls.min.js` is vendored third-party (never edit).
  - **Skill `hls-package`** (`.claude/skills/hls-package/SKILL.md`) — invoke when asked to build an HLS bundle / "make the m3u8" / convert a film to HLS. It documents the `bin/hls-package.sh` tool, source-file selection criteria, running the encode in the background, and the upload/test workflow. The encoding config (bitrate ladder, preset, fps handling) lives in `bin/hls-package.sh` itself — that script is the source of truth; edit it there to change quality.
- `library/styles/editor-ui.css` — the theme's adjustments to the block editor's own chrome (not the canvas): the sidebar featured image shown whole at its own ratio instead of core's 2:1 crop. Plain CSS outside Koala, enqueued on `enqueue_block_editor_assets` from `library/admin.php`.
- `library/admin.php` — Dashboard widget cleanup (commented out by default), the draft "Preview in new tab" icon, and the **edit-screen meta box order**: `tiagsspace_meta_box_order_first()` pins Instagram → Tumblr → Fediverse → Gallery → Video Player Options → Background & Around to the top of the normal column on every post type; the rest (Yoast, Video player(s) per post, YARPP…) follows in registered order. Done by filtering the per-screen `get_user_option_meta-box-order_<post_type>` option (bound late on `add_meta_boxes`), which `do_meta_boxes()` reads in the block editor and the classic editor alike and which moves the listed ids ahead of Yoast's `high` priority; plugin code is untouched. A plain box keeps its `add_meta_box` id, an ACF group's id is `acf-<group key>`. To change the order, edit that one list. **Toolbar**: `tiagsspace_admin_bar_tidy()` (on `admin_bar_menu`, `PHP_INT_MAX`) drops the WP logo, ⌘K command palette, front-end search, "+ New" and W3TC "Performance", and puts the posting shortcuts in the order Queue → IG → Fediverse (the dark-mode toggle stays last). To change it, edit the two lists in `tiagsspace_admin_bar_layout()`; never edit the plugins for this. **Single scroll on the block editor** (`tiagsspace_enqueue_editor_single_scroll()` + `library/js/editor-single-scroll.js`, on `enqueue_block_editor_assets`, `post` screens only): core (6.7+) renders the "Meta Boxes" pane as a resizable split under the canvas, each with its own scroll, and in 7.x the canvas is **always an iframe** (`shouldIframe: true` hard-coded in `editor.js`, no hook; an apiVersion-2 block only logs a deprecation). The pane is a flex sibling of `.editor-visual-editor` inside `.interface-interface-skeleton__content`, and core's `edit-post/style.css` forces the canvas to `flex-basis: 0; overflow: hidden`. The script sizes the canvas to its content (a `ResizeObserver` created in the iframe's own realm measures the body and writes the height on `.editor-visual-editor`), gives the iframe root `overflow: clip` and replaces core's `40vh` padding appender (vh of the iframe, a feedback loop) with `4rem`; the inline CSS on `wp-edit-post`, scoped to `body.tiagsspace-editor-flow` (added only while the flow applies), lets the canvas and the pane take their natural height, hides the drag handle and makes the "Meta Boxes" bar sticky. Caret and wheel scrolling chain from the iframe to the page by themselves; selecting a block (List View, keyboard) does not, so the script scrolls the page to a newly selected block that is off screen. It backs off to core's split when the pane is not rendered (distraction free, zoom out, every box hidden) or a device preview is on. Every lookup may fail on a core update: then nothing happens. Re-test after WP major updates.
- `library/theme-settings.php` — **Appearance → Theme Settings** (`add_theme_page`, `manage_options`). One autoloaded option `tiagsspace_settings` (an array), read with `tiagsspace_setting( 'key' )`, which merges over the defaults. Every setting is one entry in `tiagsspace_settings_schema()` (sections → fields: `id`, `type`, `default`, `label`, `checkbox_label`, `description`); the page, the defaults and the sanitizer are built from that list, so **a new setting is one array entry** (only `checkbox` is implemented: add a case to `tiagsspace_settings_render_field()` and `tiagsspace_settings_sanitize()` for another type). Plain Settings API and core markup, so the dark admin skin covers it. Current setting: `gallery_edit_published` (default off): only the **default** for the front-end gallery editor on published posts, never a gate; see the gallery editor under `library/gallery-functions.php`.
- `library/custom-post-types.php` — CPT registrations (films, dusk, hyper, 4k-lento, log, cidade — called `cityburns` / "City Series" until Nov 2026), log-branch admin filter, admin menu order, CPTs in main loop/feed/archives
- `library/redirects.php` — **every redirect particular to this installation, one list** (`tiagsspace_redirect_rules()`: exact and prefix rules, all 301, e.g. `/cityburns/…` → `/cidade/…`, `/sidewalk/` → `/log/`). Two layers from that list: PHP on `template_redirect` (what the local MAMP site uses, and a safety net) and an nginx snippet **generated** from it (`bin/redirects-nginx.php > server/nginx/tiagsspace-redirects.conf`, or `wp tiagsspace redirects nginx`), installed by hand as `/etc/nginx/snippets/tiagsspace-redirects.conf` and included **before** the W3TC include (W3TC's server-level rewrite to a cached file ends in `last`, so a rule after it never runs for a cached URL). nginx matches `$request_uri` so encoded slugs (`%c2%a7`) and query strings pass through untouched. **Change a redirect in the list, regenerate the snippet, commit both; never edit the server copy.** Lookup redirects are PHP-only and run on a 404: `/post/<old id>` (`_urbanoid_old_id`), a set moved to another series (same slug), and **old slugs stored on the post** (a slug under `/cidade/`, `/dusk/`, `/hyper/` or at the root, in one of the keys of `tiagsspace_redirect_old_slug_keys()`: `_tiagsspace_old_slug` for sets merged or renamed here, one row per slug, and `_urbanoid_old_slug`). **Never add a fixed rule for one post: store its old slug instead.** The full list of stored old slugs is generated into `server/redirects/OLD-SLUGS.md` (`bin/redirects-list.php`, or `wp tiagsspace redirects slugs`); regenerate and commit it after any change. `bin/merge-numbered-sets.php` (one-off, Nov 2026, delete once production is checked) merged 31 numbered Cidade sets ("Delirium, I/II/III" → "Delirium"): images moved to the lowest part in gallery order, the emptied parts trashed with `_tiagsspace_merged_into`, every old slug stored; log in `wp-content/merge-numbered-sets-log.json`, `--reverse` restores. Every PHP redirect sets `DONOTCACHEPAGE` (W3TC enhanced mode would store a redirect as an empty page).
- `library/migrate-cidade.php` — one-off `cityburns` → `cidade` data migration (see Custom Post Types), plus `wp tiagsspace dusk-to-cidade` (locally `bin/cidade-migrate.php --dusk-to-cidade`), which moves the 25 digital 2012–2014 Dusk sets listed in `TIAGSSPACE_DUSK_TO_CIDADE` (id => slug, checked before anything moves) to Cidade: **Dusk is the analog series**. Keep the file until both environments are done and checked; both commands are idempotent and have `--reverse`. A set moved between series keeps its slug; `library/redirects.php` sends a 404 under `/dusk/`, `/cidade/` or `/hyper/` to the same slug in another series.
- `library/custom-taxonomies.php` — Taxonomy registrations (places, medium, log-branch, from), admin taxonomy filters, CPTs on tag archives, disable categories
- `library/template-functions.php` — Template helpers: taxonomy_list(), content_wrap(), background colors, number/stats helpers, attachment margins, media counts, [last_post_link] shortcode, `tiagsspace_post_gallery_ids($post_id, $mime = '')` (attachments in a post's default gallery, honouring `remove_from_default_gallery`; used by the archive table, the OG image and the label), `tiagsspace_series_name($post_type, 'archive'|'single')` (the name search engines read — "Dusk Series", "Hyper Series", "Cidade Series", "4K Lento Mixes" / "4K Lento Mix", "Films" / "Film", "Log" — used by the `<title>` templates and share cards) and `tiagsspace_series_ui_name()` (**what the page shows, plain words: "Dusk", "Hyper", "Cidade"**, other types as `tiagsspace_series_name()`; used by the menu, the header line, a set's type crumb and the thumbnail hover label. Tiago, Nov 2026: no "Series" anywhere in the UI, simple and not pretentious; "Series" only in the SEO title) (the short forms shown on phones, "4K Lento", live in `library/page-title/config.php`), `tiagsspace_versioned_media_url()` (appends a `?v=<filemtime>` to an uploads URL so a file replaced in place defeats the 1-year media Cache-Control; used by the archive teaser `<source>` tags in `template-parts/archive-grid.php`), `tiagsspace_gallery_item_spans()` / `tiagsspace_gallery_item_factor()` / `tiagsspace_gallery_sizer_spans()` (gallery item widths and the Masonry sizer, see **Masonry and image loading**), `tiagsspace_once( $key )` (true the first time a key is seen in a request: vendor `<script>` tags and the lead gallery, which a template part must print once per page even when it renders once per Log entry)
- `library/page-title/` — **The page-title module**: one model and one renderer for every line that says where the visitor is — the fixed header line ("Tiags' Space / Dusk / Them"), a listing's entry title after each gallery, and the label the header shows while a thumbnail is hovered. `config.php` holds the words (which post types get a type crumb, short forms, taxonomy words "Medium" / "Dating" / "Place" / "Tag", the films archive word "Film"); `crumbs.php` builds crumb lists (`tiagsspace_entry_crumbs($post_id, ['omit', 'link_title'])`, `tiagsspace_page_crumbs($query)`), data in, data out, no HTML, no globals; `render.php` (`tiagsspace_render_crumbs($crumbs, $args)`) is the only place HTML is written. Callers: `header-title.php`, `entry-body.php`, `archive-grid.php`. **Read `library/page-title/README.md` before touching any of it.** `bin/page-title-snapshot.sh <file>` writes what the module renders on a fixed list of local pages; take one before and one after a change and diff them. The module also sets the body class `header-entry-title` on every singular view whose header carries a work's title.
- `library/seo-and-feed.php` — Feed links, Feedly support, feed title/content formatting, plus the theme's SEO layer on top of Yoast:
  - **Link-preview image**: no dedicated size. `tiagsspace_share_image_array()` picks the **largest existing size under `TIAGSSPACE_SHARE_IMAGE_MAX_BYTES` (280 KB)** — medium 940 → medium_large 768 → small 720 → thumbnail 480 — because **WhatsApp stops rendering previews around 300 KB** (a quarter of the 940px files are over it). Reads the `filesize` stored in the attachment metadata, falling back to a stat. Never add a `share` image size again: it cost 1.1 GB for nothing.
  - **Open Graph image**: `tiagsspace_add_opengraph_image()` on Yoast's `wpseo_add_opengraph_images` container — featured image (else first non-hidden gallery image) on singles, latest post's featured image on archives/taxonomies/home. Uses the size picker above. Never swap the URL through `wpseo_opengraph_image`: that leaves Yoast's precomputed `og:image:width/height` for a different file (the old bug).
  - **`%%label%%` Yoast variable** (`tiagsspace_seo_label()`): the "museum wall label" meta description built from existing data — count + kind (from the deepest `medium` term), medium, `places`, `from` years; films get "Film, N min" (HLS bundle or attachment duration); `4k-lento` uses the medium term as the kind ("DJ Mix"). One–twelve spelled out, digits from 13. Language follows `set_language`. **Layer 2**: a hand-written Yoast description (`_yoast_wpseo_metadesc`) is rendered followed by the label (`wpseo_metadesc` + `wpseo_opengraph_desc`), trimmed to ~155 chars by dropping medium, then count. Never generate Layer 2 text.
  - **Archive figures**: `tiagsspace_archive_stats( $scope )` counts sets, images and the first/last `from` year for a scope returned by `tiagsspace_archive_scope()` (a term, a series, or the whole archive). Counts only what a visitor can reach: published sets not flagged `hide_post_from_main_page_archives_and_feed`, images not flagged `remove_from_default_gallery`. A parent `medium` term counts its children. One 6 h transient per scope, all dropped when a set is published or unpublished (`tiagsspace_archive_stats_salt`).
  - **Copy rules (Tiago, 27 Sep 2026)**: the site sentence is `A speculative archive by Tiago H. G.` ("fictional", "open", "docufiction" are retired). Sets are counted exactly. Images are rounded **down** (`tiagsspace_round_figure()`: to the hundred from 100, to the ten from 10 to 99, exact below 10) and carry **"more than"** only when rounded. One to twelve spelled out. A single year reads "in 2016" / "from 2016", never "between 2016 and 2016". Descriptions are full stative sentences: no dash, no call to action, no stock phrase.
  - **`%%archive_label%%`** (`tiagsspace_archive_label()`): the whole description of an archive page, one sentence per type, wording chosen by Tiago — series "A series of 127 sets and more than 1,100 images made between 2007 and 2025.", Log "A log of … entries", 4K Lento "A series of 36 DJ mixes recorded between…", Films "Eight films made between…", place "335 sets and more than 3,600 images made in Berlin between…", medium "iPhone, the medium of …", year "23 sets and more than 100 images dated from 2024.", log branch "Still, a branch of the Log with …", tag "beach, a tag on one set of eight images dated from 2016." All eleven archive description templates in Yoast are this one variable. **Do not reword these sentences or bring back the old jokes without asking.**
  - **Whole-archive variables** for the home and Index sentences: `%%archive_sets%%`, `%%archive_images%%` (includes "more than"), `%%archive_years%%` ("2007–2026"), `%%archive_between%%` ("between 2007 and 2026").
  - **Search titles (`<title>`): the patterns live in the theme**, in `tiagsspace_title_templates()` — not in Yoast's settings screen. A title names the work first, then what it belongs to, joined by **` ‹ `** ("Away ‹ Dusk Series ‹ Tiags' Space", "Berlin ‹ Place ‹ Tiags' Space"). The home title is "Tiags' Space · Tiago H. G." (two names side by side, so a middle dot). **The slash is only for folder order, which is how the page itself reads** (header, set heading, hover label). Series words come from `tiagsspace_series_name()`. An `init` routine writes the list into Yoast's `wpseo_titles` option whenever the list changes (hash in `tiagsspace_title_templates_hash`), so a pattern edited in Yoast's settings is replaced at the next change here: **change titles in the theme**. Home, post type archives, date archives, search and 404 also take their pattern straight from the list through `wpseo_frontend_presentation`, because Yoast renders a stored copy for those and refuses to refresh it when `wp_get_environment_type()` is not `production` (the local site is `local`). A title written by hand on one post (`_yoast_wpseo_title`) still wins; write it with ` ‹ ` too. Patterns for content that no longer exists (podcast, emulsion, series, film_genre, category) are left in the database untouched.
  - **Share cards carry bare titles** (`tiagsspace_bare_share_title()` on `wpseo_opengraph_title` / `wpseo_twitter_title`): the work's title, the series name, the term name. ### Gallery spacing (the gap)
One number per gallery, the **gap**, drives all space around and between images (Nov 2026; the five `spacement-N` SCSS blocks, `.row-inverted` and the "No space" checkbox are gone).
- **Resolver**: `tiagsspace_gallery_gap()` in `library/template-functions.php` returns `0`, `2`, `4`, `8`, `16`, `20` or `'default'` (the page gutter: 16px, 12px below `lg`). `tiagsspace_gallery_gap_normalise()` maps what is stored against a whitelist, so no field text reaches the markup: the retired `no_space` tick → 0, `spacement-N` → N, the old label `: 40px (Theme Gallery)` or nothing → default. **No database migration was run; the legacy values are still in the database and must stay readable.**
- **Editor**: one ACF radio "Space between images" (field `spacement`, key `field_558b40147ee22`, hidden for horizontal galleries, which never used it). Two filters at the end of `library/acf-fields.php`: `acf/load_value` shows a legacy state as the matching choice, `acf/update_value` writes `no_space = 0` on save (with `update_metadata()`, because a preview saves to the revision).
- **Output** (`template-parts/entry-gallery.php`): gap 0 → row `row no-pad`, images edge to edge (Dusk, Hyper, Blwww, Hrzn, Still by default); any other gap → `.gallery-gapped` on `.container-gallery`, plus an inline `--gallery-gap: Npx` when a value was chosen. Cidade's built-in default is `'default'`, the theme spacing (many Cidade posts have 20px stored and keep it). `$class_container` is whitelisted to `container` / `container-fluid`. `$gallery_fixed_width` is true only for a no-gap Container gallery; `gallery-item.php` uses it to choose between the 1200px `sizes` and viewport fractions.
- **SCSS** (`_layout-grid-spacing.scss`, one block): the gap is the same horizontally and vertically at every width; **the side margin is the theme's line for Container and Full width alike** (12px below `lg`, 16px from `lg`, the tokens `.side-padding` and the thumbnail grid use), so a gallery starts where the header, Previous/Next and the related thumbnails start; a Container gallery with a gap is therefore not centred (`max-width: none`), only a no-gap Container gallery is (Tiago, Nov 2026); under the gallery there is `.container-gallery`'s `padding-bottom` + the gap. **Never add a per-value block again**: a new value is one entry in `tiagsspace_gallery_gap_values()` and one ACF choice.
- **"Item Max heigh" (ACF `item_max_heigh`, Left / Right; no image taller than 90vh)**: capping only the `<img>` left it narrower than its column, so a strip of page showed between images in any window shorter than a column's image (it looked browser-specific; it is the window height). Without Masonry the row is now a CSS grid, `.gallery-max-heigh-grid` in `_page-single-gallery.scss`: `entry-gallery.php` passes the column counts inline (`--cols-xs/sm/md/lg`), `gallery-item.php` each image's width/height (`--item-ar`), and each item is as wide as the smaller of its share of the row (`100cqw / --cols`, the row is a size container) and `90vh × --item-ar` (+ the gap in a gapped gallery). Columns shrink with the images and pack left or right (`.gallery-max-heigh-right`); the column count per breakpoint is unchanged. Behind `@supports (width: 1cqw)`; Masonry galleries keep the old image-only cap. **Sass traps met here**: write CSS `min()` through `unquote("min(…)")` (this Sass computes `min()` itself and fails), and never give a `var()` a `0px` fallback inside `calc()` (the minifier writes `0`, which is invalid there).
- **Asset versions**: every theme CSS/JS URL carries `?ver=<filemtime>` (`tiagsspace_asset_ver()`), the vendored ones in `functions.php` and the inline `<script>`/`<link>` tags in the gallery templates included, so a deploy changes the URL of whatever file changed. A new asset must do the same; never pass `null` as the version.
- `.thumbnail` transitions only `opacity` and `box-shadow` (Nov 2026; it was `all .2s`). Never put `all` back: width, padding and margin must change at once, because Masonry measures the items right after a breakpoint change, and a 0.2s width animation gave it mid-animation sizes (wrong spans, overlaps or holes until the next resize).

**Page background per type** (`color_background_parameters()` in `library/template-functions.php`): Hyper, Dusk, Cidade (since Nov 2026) and Log get the body class `white-darkmode` (white, `$dark` under `prefers-color-scheme: dark`); Films and 4K Lento `dark`; other singles plain `white`, which ignores dark mode.

### Favicons
- Two icon sets, both **generated from an Apple emoji** by `bin/favicon-from-emoji.js` (macOS JXA + AppKit, run with `osascript -l JavaScript`; no compiler, no Pillow — the Swift toolchain on this Mac is broken, don't reach for it): `favicon.ico/` is the site (💿, a round emoji so Google's circular crop loses nothing) and `favicon.ico/adminarea/` is wp-admin (📿). To change an icon, run the script with the new emoji and the target dir; **never hand-edit the PNGs**. The glyph is cropped to its alpha bbox and scaled to fill the canvas with zero margin; `apple-icon-*` get an opaque `--touch-bg` (default `#ffffff`) because iOS blackens transparency, everything else keeps alpha; `favicon.ico` is PNG-in-ICO 16/32/48; `manifest.json`/`browserconfig.xml` are rewritten with paths relative to themselves (the old absolute `/android-icon-…` ones 404'd).
- `functions.php` emits both sets through one helper, `tiagsspace_favicon_links($subdir)`, on `wp_head` and `admin_head`. Every href carries `?v=<filemtime>` via `tiagsspace_asset_ver()` so a regenerated icon replaces the cached one after deploy. Includes a 48px `rel=icon` (the multiple Google asks for) and the `.ico` with `sizes="any"`.
- **Root-path requests**: Firefox iOS fetches `/favicon.ico` at the domain root instead of the `<link>` tags, and with no Site Icon set WordPress core answers that with a 302 to its own W logo (`do_favicon()`), which Firefox then cached. `tiagsspace_site_icon_fallback()` filters `get_site_icon_url` (checks `get_option('site_icon')`, **not** `has_site_icon()`, which calls `get_site_icon_url()` and would recurse) to return the theme `.ico` for sizes ≤48 and the 192px PNG above; this also fixes the REST index `site_icon_url`. `tiagsspace_root_touch_icon_redirect()` on `init` 301s `/apple-touch-icon.png` and `-precomposed.png` to the 180px touch icon. Locally `/favicon.ico` 404s because the MAMP install's rewrite rules lack WP's `favicon` rule; test with `index.php?favicon=1` instead. Never set a Site Icon in the Customizer: it would emit a second set of `<link rel=icon>` tags on top of ours.

### Fonts
- Font files live in `library/fonts/`
- Only active font: `lora/` (Lora, SIL OFL, files from `@fontsource/lora` 5.3.0, **woff2 only**; 400 + 600, normal + italic)
- **Every face ships as two subsets with `unicode-range`**: `lora-latin-*` (A–Z, digits, Latin‑1 accents — every page) and `lora-latin-ext-*` (U+0100 and up — fetched on demand). The ext subset alone has **no basic letters**: shipping it without the latin file, or without the ranges, makes the whole site silently render in Times. Declared by a loop in `_foundations-fonts.scss` (`@font-face`, `font-display: swap`) via relative paths `url('../fonts/lora/...')`.
- `functions.php` preloads `lora-latin-400-normal.woff2` on `wp_head` (priority 1) so the first paint is Lora, not the fallback serif.
- `library/styles/editor-style.css` (Gutenberg, via `add_editor_style`) is plain CSS outside the Koala pipeline and repeats the same eight `@font-face` rules; **update both files together** when the font files or ranges change. It also hard-codes the prose size (`$font-size-content`, currently 23px) and Bootstrap's h1–h6 scale so the canvas matches the front end; **whenever `$font-size-content` or the heading scale changes, change `editor-style.css` too.** **Canvas text colour is set once on `body` (`#000`) and `p`/`h1–h6`/`a`/lists say `color: inherit`**, so the dark-mode plugin's own body colour (it recolours `body.dark-mode.editor-styles-wrapper` in the iframed canvas and TinyMCE's body) reaches every element; never put explicit text colours or a `prefers-color-scheme` block back in that file: the plugin has a manual toggle, so the OS scheme and the admin skin can disagree, which is what left the post title black on the dark canvas (Nov 2026).
- Rendering: `body` sets `-webkit-font-smoothing: antialiased` / `-moz-osx-font-smoothing: grayscale` (macOS only) to match the fontsource.org reference. Nothing else: `font-feature-settings`, `font-kerning`, `text-rendering` stay at browser defaults (kern/liga/calt are already on).

## Header logic
The fixed top-left line (`template-parts/header-title.php`) is the page's title everywhere, built by `library/page-title/` from a list of crumbs (`tiagsspace_page_crumbs()`):
- Home, search, 404: "Tiags' Space" (never shortened).
- Archives and taxonomy pages: "Tiags' Space / Dusk", "Tiags' Space / Place / Berlin", "Tiags' Space / Log / Blwww", "Tiags' Space / Film" (the films archive word is a config override). Series words come from `tiagsspace_series_ui_name()` (plain "Dusk", "Hyper", "Cidade": never "Series" in the UI); the site name and 4K Lento's added word "Mixes" are shortened below `sm` (`d-none d-sm-inline`), so a phone shows "S / Dusk" and wider screens "Tiags' Space / Dusk". The Index page reads "Tiags' Space / Index".
- **Single works (since Oct 2026): the work's title is in the header too** — "Tiags' Space / Dusk / Them", "Tiags' Space / Log / Blwww / Thunder", a film "Tiags' Space / Hotel" (no series crumb), a page "Tiags' Space / About". The title crumb is the inline `<h1>`; everything after the site crumb sits in `<span class="site-title-entry">`. The top-right word stays the short "R" on singles. On phones (below `sm`, body class `header-entry-title`) the line may use the whole width left of "R" (`max-width: calc(100vw - 72px)`) and is `position: absolute` instead of fixed, so it scrolls away with the page: a long title reads once at the top instead of sitting over the photograph. Archives keep the fixed header at every width.
- **Thumbnail hover label** (`archive-grid.php`, shown from the sm breakpoint in `#over-text`): built by the module into a `data-label` attribute (`esc_attr`), and the figure calls `showText(this.dataset.label)` — no PHP writes JavaScript any more; `data-year` feeds `showYear()`. On an archive the label is **appended** after the page title, so it starts with " / "; on a series archive it is only the set's title; on taxonomy pages it keeps the " > Space" root. On a single work (the related sets) `header-helpers.js` **swaps** everything after "Tiags' Space / " for the label while hovered (only from `sm` up, where the span is displayed; a touch tap never blanks the title) and restores it on leave; focusing a thumbnail's link does the same. A series' added word (only 4K Lento's "Mixes" now) shows from `md` on the home page, from `xl` on archives and from `sm` on singles (the header's own rule).
- **Menu**: Hyper, Dusk, Cidade (plain words, no "Series"). **4K Lento stays short in the menu**: "4K Lento Mixes" (258px) is wider than the menu column and wraps onto two lines from 768px up.

When adding new post types or taxonomies, add them to `library/page-title/config.php` (one line each) and add menu entries in the collapseMenu section of `header-menu.php`.

**Reveal/Hide word**: the `.reveal`/`.hide` spans are switched by CSS on the trigger's `aria-expanded`. The trigger collapses three targets at once (`.multi-collapse`: menu, top title, lower date), and Bootstrap rewrites `aria-expanded` after each, ending on a hidden title, so the word came out inverted. `library/js/header-helpers.js` (`bindMenuWord`) sets it from `#collapseMenu`'s own `shown/hidden.bs.collapse` events (ignoring bubbled nested collapses). Don't add `aria-expanded` logic elsewhere.

**Header text colour** (`_region-header-nav.scss`): the title block (`#site-header .topbar-left`), the Reveal/Hide word (`#topbar`) and the lower bar (`#lower-header`, shrink-wrapped to the hover date) are each `position: fixed`, transparent, `mix-blend-mode: difference` with a white text base, so they read as the inverse of whatever is behind them. Only those small boxes blend (the GPU reads back exactly their area per frame), never a full-width bar. `#site-header` itself is a zero-height `position: absolute` container with no blend and `pointer-events: none`; it must **never** get `position: fixed`, a `z-index`, `opacity`, `transform` or `filter` (each makes it a stacking context, and the children would blend against the empty header instead of the page). `.topbar-left.collapsing` is forced back to `fixed` because Bootstrap's `.collapsing` sets `position: relative`. The blend resolves against the **root** group; the `<html>` background in `_foundations-tokens.scss` is the base over plain areas. **Never put `isolation: isolate` on `<body>`** (or any ancestor of the blocks): it makes the page an off-screen surface that Firefox re-rasterises in pieces after a re-layout (menu collapse, fullscreen exit) and leaves 1px horizontal seams across the viewport. Per-scheme/background colour rules still apply to the menu (`.slicknav_nav`, `#collapseMenu`) only.

### Masonry and image loading (Nov 2026)
- **One setup for every grid**: `tiagsspaceMasonry( element, options )` in `library/js/masonry-grid.js` (handle `tiagsspace-masonry`, in `<head>` after `masonry-pkgd`), called inline right after the gallery (`entry-gallery.php`) and the archive grid (`archive-grid.php`). It returns the jQuery instance, so `$grid.data( 'masonry' )` keeps working for the editor scripts. **No imagesLoaded anywhere** (the `imagesloaded` enqueue is gone): every item reserves its height with the `.imgcontainer` `padding-bottom: <ratio>%` box, so Masonry lays out before the first paint instead of after every image on the page had downloaded. A new grid item must reserve its height the same way. The helper also snaps the column to an exact fraction of the row (Masonry measures the sizer to 1/64 px, an error that grows with each column: hairlines in edge-to-edge galleries) and relays out, instantly and once per frame, when an item's **height** changes with its width unchanged (`ResizeObserver`: 3D models, audio players, captions after the web font; a width change is a window resize, which Masonry handles itself).
- **Gallery sizer = GCD of the item spans** (`tiagsspace_gallery_sizer_spans()`, per breakpoint, hidden-pool items included in edit mode). Masonry rounds an item's span UP to whole sizer columns: the old fixed `col-4` sizer turned a 1.5x image (`col-md-21`) into 24/48 and left a 3/48 hole beside it. Uniform galleries keep their own columns (16/48 for three). The span maths is `tiagsspace_gallery_item_spans()`, shared with `gallery-item.php`; never compute spans a second way. The archive grid keeps its fixed 1/48 sizer.
- **Image loading, one decision per request** (`$gallery_eager_items` in `entry-gallery.php`): only the first gallery of the request (`tiagsspace_once( 'lead-gallery' )`, not on paged/Infinite Scroll requests; `entry-gallery-horizontal.php` claims the slot too) loads its first `$number_of_columns_lg` images at once, and its image 1 gets `fetchpriority="high"` unless a film player sits above it. Everything else is `loading="lazy" decoding="async"`: later rows, every later gallery (one per Log entry), the hidden pool (`display:none`, so its images now load only when revealed). Animation galleries (`swap-randomly-positions-constant-frequency`) load everything, because they show images on a timer. Archive thumbnails: the first 8 of an archive's first page are eager, the rest lazy, and every related thumbnail under a set is lazy.
- **Infinite Scroll never gets the `outlayer` option**: with it, Infinite Scroll runs its bundled imagesLoaded on each new page BEFORE inserting it, and lazy images in that detached page never load, so the page would never come. `archive-grid.php` calls `msnry.appended( items )` itself in its one `append.infiniteScroll` handler (which also runs the Safari srcset re-parse once and queues the teasers). `archive-log.php` appends whole entries, whose own gallery scripts Infinite Scroll 4 runs. Both listings start Infinite Scroll through `tiagsspaceInfiniteScroll( selector, options )` in `library/js/infinite-scroll-setup.js` (printed after the vendored pkgd file): the next page is asked for at `max(1600px, 2.5 × window height)` from the bottom (kept current on resize; a page of thumbnails is about one screen and up to a second to arrive), the distance is checked again after each append so loading goes on when the visitor stops scrolling, there is **no page limit** (the "More" button after 15 pages is gone, Nov 2026), and the srcset re-parse runs on WebKit only. On the archive grid, appended thumbnails fade in (`hiddenStyle`/`visibleStyle` opacity only, stagger 10ms), no scale pop.
- **Once per page**: the Magnific / Intense / model-viewer `<script>` tags and the gallery video observer are printed through `tiagsspace_once()`. The gallery video observer is one page-wide `IntersectionObserver` (`window.tiagsspaceGalleryVideoObserver`; observed containers get `data-video-observed`), because its script runs again with every gallery and every appended Log page.

**Archive thumbnails, performance**: teaser `<video class="plyr-thumbnail-front">` markup carries `preload="none"` and **no `autoplay`** (with them the browser fetched every teaser on the page at load and started each one wherever it was). `footer.php` sets one up when it comes within 600px of the viewport (`queueInitializePlyrOnIntersect()`, also called for Infinite Scroll pages) and plays / pauses it through **one shared observer** (`observeThumbPlayback()`, `data-in-view`); a teaser that finishes loading off screen does not start. No scroll handlers in templates. Thumbnail `<video>` gets no `filter`/`transform` at rest (an identity filter still costs a filter pass per decoded frame). The grid `<figure>` uses `onmouseenter`/`onmouseleave` (not the bubbling `mouseover`/`mouseout`) to feed `showText()`/`showYear()` in `library/js/header-helpers.js`, which only write when the label changes.

## Deployment
The theme is deployed via GitHub: push to `main` triggers a webhook (`/hook-tiagsspace`) on the production server (Ubuntu 24.04 / nginx / PHP 8.4), which runs `git pull` in `/var/www/tiagsspace/wp-content/themes/tiagsspace` and flushes W3 Total Cache. The deploy script (`/var/www/webhooks/tiagsspace/deploy.php`) verifies the GitHub HMAC-SHA256 signature and only acts on `refs/heads/main`. See README.md § Deployment for full details. A push does **not** update nginx: when `server/nginx/tiagsspace-redirects.conf` changes, it has to be copied to `/etc/nginx/snippets/` by hand (sudo), then `nginx -t` and a reload. The production server is Linux (case-sensitive filesystem), while local development is macOS (case-insensitive).

**Important:** When renaming files or directories with only a case change (e.g. `Sporting-Grotesque` → `sporting-grotesque`), macOS won't detect it. You must use `git mv` with a two-step rename (via a temp name) so Git tracks the change:
```
git mv old-Name temp-name && git mv temp-name new-name
```
Otherwise the server will still have the old-cased directory and paths will 404.
